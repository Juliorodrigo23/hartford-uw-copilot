02
Service account, IAM roles, and secrets
~5 min

Cloud Run runs as a dedicated service account. We grant it just two roles — Vertex AI User (to call Gemini) and Secret Manager Secret Accessor (to read the HMAC + OpenAI keys at boot).

# Service account + IAM
PROJECT_ID=$(gcloud config get-value project)
REGION=us-central1

gcloud iam service-accounts create uw-copilot-runner \
  --display-name="UW Copilot Cloud Run runtime"

gcloud projects add-iam-policy-binding "$PROJECT_ID" \
  --member="serviceAccount:uw-copilot-runner@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/aiplatform.user"

gcloud projects add-iam-policy-binding "$PROJECT_ID" \
  --member="serviceAccount:uw-copilot-runner@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
# Secrets · keep $HMAC for the Vercel step
HMAC=$(openssl rand -hex 32)
echo -n "$HMAC" | gcloud secrets create hmac-secret --data-file=- --replication-policy=automatic

# Optional · used by the LLM-as-judge eval track only
gcloud secrets create openai-api-key --replication-policy=automatic
echo -n "sk-..." | gcloud secrets versions add openai-api-key --data-file=-

# Artifact Registry repo for the backend image
gcloud artifacts repositories create uw-copilot \
  --repository-format=docker --location=$REGION

echo "save this for the Vercel env step:"
echo "HMAC=$HMAC"
Save this Copy the $HMAC value to a password manager. You'll paste it into Vercel as HMAC_SECRET in step 4.

If build fails Most common cause: missing IAM role for the Cloud Build service account. Run gcloud projects add-iam-policy-binding $PROJECT_ID --member="serviceAccount:$(gcloud projects describe $PROJECT_ID --format='value(projectNumber)')@cloudbuild.gserviceaccount.com" --role="roles/run.admin" and re-submit.

Deploy frontend to Vercel
~3 min

From the frontend/ directory. Link a new project, set three env vars, and ship. The site builds in ~90 seconds.

# From frontend/
cd "/Users/JulioContreras/Desktop/Hatford Cla/frontend"

vercel link        # accept prompts; pick a project name like uw-copilot-hartford
vercel env add BACKEND_URL production           # paste the Cloud Run URL from step 3
vercel env add HMAC_SECRET production           # paste the $HMAC from step 2
vercel env add NEXT_PUBLIC_BASE_PATH production # paste exactly: /hartford

vercel --prod

Vercel prints a production URL like uw-copilot-hartford.vercel.app. Open https://uw-copilot-hartford.vercel.app/hartford to confirm the basePath is correct — the landing page should render with the particle hero.

Why three env vars? BACKEND_URL is where the API route proxies to, HMAC_SECRET signs each request so randoms can't hammer your Cloud Run, NEXT_PUBLIC_BASE_PATH matches basePath in next.config.ts so client-side fetches resolve correctly.

05
Surface it at juliooo.com
depends on routing choice

Two paths. The right one depends on where juliooo.com is hosted today.

Where does juliooo.com run?

Path A — Subpath rewrite at juliooo.com. Add this to your main site's vercel.json:

juliooo.com/vercel.json
{
  "rewrites": [
    {
      "source": "/hartford/:path*",
      "destination": "https://uw-copilot-hartford.vercel.app/hartford/:path*"
    }
  ]
}

Replace uw-copilot-hartford.vercel.app with the actual production URL Vercel gave you in step 4. Redeploy juliooo.com. The Hartford project keeps basePath: '/hartford' and the subpath just works.

Test:

# bash
curl -I https://juliooo.com/hartford
# expect: 200 with Content-Type: text/html

Path B — Subdomain. Easier than a cross-host rewrite. The site lives at hartford.juliooo.com instead of juliooo.com/hartford. UX is identical.

1. In the Vercel project: Settings → Domains → add hartford.juliooo.com. Vercel shows a CNAME target.

2. At your DNS host:

DNS · CNAME record
hartford   CNAME   cname.vercel-dns.com.

3. In frontend/next.config.ts: comment out the basePath and assetPrefix lines, and update NEXT_PUBLIC_BASE_PATH to empty string in Vercel env. Redeploy with vercel --prod.

frontend/next.config.ts
// const basePath = process.env.NEXT_PUBLIC_BASE_PATH || "/hartford";
// basePath,
// assetPrefix: basePath,
Why this is easier No cross-host rewrite means no risk of header mismatch, asset paths just work, and DNS propagation is the only thing that can go wrong.

Troubleshooting cheat-sheet

Common errors and what to do

403 Permission denied on Vertex AI Service account missing roles/aiplatform.user. Re-run the IAM binding from step 2.
SSE stream returns instantly with no events Cloud Run is buffering. Make sure x-accel-buffering: no is set on the response (the API route already does this).
Chat returns 401 unauthorized HMAC signature mismatch. Confirm HMAC_SECRET in Vercel matches the hmac-secret value in Secret Manager. To bypass during dev, set ALLOW_UNSIGNED_DEV=true on Cloud Run (do not leave this on in prod).
"basePath" 404s on /hartford/data/*.json Either the static files weren't generated (run script 08) or NEXT_PUBLIC_BASE_PATH doesn't match what's in next.config.ts.
Cold starts feel painful First request after idle takes 3–5s. For an interview window, set min-instances=1 (see ops section). Memory cost only, ~$0.43/day extra with default CPU-on-request, ~$4.60/day with CPU-always-allocated.
